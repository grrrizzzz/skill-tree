# Phase 2: Gap Analysis

> **Directory:** `02-gap-analysis/` | **Internal Reference**

---

## What This Phase Accomplishes

Gap analysis is where you measure the distance between where the client is and where ISO 42001 requires them to be. Working clause by clause through the standard, you assess the client's current practices, policies, and records against each requirement and score the gaps by severity. The output is a prioritized gap register that becomes the blueprint for Phase 3 remediation. This phase requires close collaboration with the client — you'll need access to existing policies, process documentation, and the people who actually run the AI systems. A well-executed gap analysis prevents surprises at the certification audit.

## Phase Outputs

Phase 2 produces:

- **Gap Analysis Workbook** (`template-gap-analysis-workbook.md`, completed) — the detailed clause-by-clause assessment with evidence notes and gap scores. This is the working document; it stays with the consultant and client project team.
- **Gap Analysis Report** (`template-gap-analysis-report.md`, completed) — the executive-facing summary of findings, prioritized gaps, and recommended remediation sequence. This goes to the client sponsor and informs Phase 3 planning.

---

## Estimated Duration

**1–2 weeks** for a typical SMB engagement. This includes document review, gap analysis sessions (usually two to three working sessions), scoring, and report drafting.

Clients with no prior ISO management system experience tend to have more gaps and require more session time to explain requirements. Budget extra time for these engagements.

---

## Key ISO 42001 Clauses Addressed

Gap analysis covers the full standard, but these clauses most commonly surface significant gaps in SMB AI-user organizations:

| Clause | Topic |
|--------|-------|
| 4.1–4.4 | Context, interested parties, scope, AIMS establishment |
| 5.1–5.3 | Leadership, AI policy, roles and responsibilities |
| 6.1–6.2 | Risk assessment, AI objectives |
| 7.1–7.5 | Resources, competence, awareness, communication, documented information |
| 8.1–8.6 | Operational planning, AI risk treatment, impact assessment, supplier management |
| 9.1–9.3 | Monitoring, internal audit, management review |
| 10.1–10.2 | Nonconformity, corrective action, continual improvement |
| Annex A (A.2–A.10) | AI system controls |

## Notes for This Phase

Scoring consistency matters. If you rate gaps differently across sessions or clients, the gap register loses credibility as a planning tool. The procedure includes a scoring rubric — use it for every finding, not just the borderline ones.

Clients sometimes push back on gap findings, particularly around leadership and governance clauses. Document the evidence (or lack of it) carefully. The gap register is a factual record, not a negotiation. That said, how you present findings to leadership affects whether they act on them. The gap report template is structured to lead with business impact, not clause numbers.
